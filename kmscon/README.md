## Dynamic theme — how it works (and rules)

The palette is **generated by matugen, never hand-edited**:

1. Wallpaper changes → `dms matugen queue …` runs automatically (or manually
   via `~/dotfiles/kmscon/regen-theme.sh`).
2. matugen renders `dms/matugen/kmscon-palette.conf` (hex colors from the
   wallpaper) → `~/.cache/kmscon/matugen-palette.conf`.
3. matugen's `post_hook` pkexec-runs the hardened helper, which splices the
   `# BEGIN DMS MATUGEN PALETTE` block into `/etc/kmscon/kmscon.conf` and
   leaves every other line untouched.

⚠ The `/etc/kmscon/kmscon.conf` palette block is a *runtime artifact*. The
dotfiles copy of `kmscon.conf` intentionally contains **no** palette; after
installing it, run `~/dotfiles/kmscon/regen-theme.sh` once to restore the
palette. Never copy a palette back from `/etc` into managed files.

## Input reality (verified against the actual kmscon source)

kmscon does **not** use libinput — it opens the keyboard/mouse/trackpad evdev
devices directly. Consequences:

- No libinput config files, quirks, or tap-to-click settings apply. There are
  no config options beyond `mouse=` / `natural-scrolling=`.
- **Selection (built-in, no config needed):**
  - left-drag → select; release → copy (to kmscon's internal buffer)
  - **double-click → select word + copy** (dbl-click window is hard-coded <500 ms)
- **Paste:** two-finger click or two-finger tap on your touchpad → the kernel
  emits `BTN_TOOL_DOUBLETAP`, which kmscon maps to its paste button.
  A physical right-area click (`BTN_RIGHT` from the clickpad's button plane,
  present on your Elan pad) is mapped by kmscon to only *reset* the selection,
  not paste.
- **Scroll:** two-finger scroll works through the pad's emulated wheel node;
  keyboard grabs also exist (`Ctrl+Shift+Up/Down`, `Ctrl+Shift+PgUp/PgDown`).
  `natural-scrolling=on` inverts the wheel direction.
- Tap-to-click, click-method, middle-emulation etc. **do not exist** — the
  evdev code is what it is; only a source patch could change that.

## Copy/paste & screenshots — why no keybinds

kmscon's grab list is fixed (scroll / zoom / session / rotate / reboot): no
exec, copy, or paste grabs, and a bare DRM tty has no clipboard owner for an
external clipboard to exist. So:

- **Ctrl+Shift+C / Ctrl+Shift+V — not implementable.** Use the built-in
  selection + two-finger paste above; run `tmux` inside kmscon if you need
  terminal-driven copy/paste.
- **Super+Shift+S — not bindable inside kmscon.** Helper instead:
  `sudo ~/.local/bin/kmscon-screenshot` (ffmpeg kmsgrab → PNG in
  `~/Pictures/Screenshots`; passwordless via `/etc/sudoers.d/kmscon-screenshot`,
  installed and visudo-validated). Run it from the tty shell, another VT, or
  ssh. Super+Shift+S inside the Hyprland/DMS session is untouched.

## Greeter & VT layout

- DE default greeter: `greetd` (`display-manager.service` symlink) running
  `dms-greeter --command hyprland` on tty1 — unaffected by any of the kmscon
  setup. Kernel cmdline has no console/tty forcing (`systemd.unit=` etc).
- VT switching (Ctrl+Alt+F2+): systemd-logind auto-spawns `autovt@ttyN`,
  repointed to `kmsconvt@.service` (Fedora's UseKmsconVTConsole implementation;
  kmscon 10.0.4 matches Fedora's version) → kmscon per-VT while getty stays
  as `OnFailure` fallback. Wiring:
  ```sh
  pkexec ln -s /usr/lib/systemd/system/kmsconvt@.service /etc/systemd/system/autovt@.service
  pkexec systemctl daemon-reload
  ```
- **tty1 is masked**: `/etc/systemd/system/kmsconvt@tty1.service -> /dev/null`
  (pkexec) so the DMS greeter has tty1 exclusively. Without the mask kmscon
  fights the greeter for VT1/DRM master at boot (slow, flickering start).
  Re-enable it someday and you get a fallback login where greetd was — config
  lives in the greeter config's backup rotation, not here.
